# Freezer Memo UX Audit

**Date:** 2026-09-04

**Scope:** Core inventory and settings flows in the React/PWA implementation.

**Method:** Local mobile and desktop walkthrough, source inspection, automated interaction path, build, lint, and test verification.

## User path audited

Fresh start → Add item → Save → Inventory → Edit → Take out → History → Settings

The local build and lint passed. All 42 unit tests passed, and the automated interaction path completed without console errors. The findings below concern UX, hierarchy, feedback, recovery, and state design.

## Findings

| Severity | Finding | Concrete fix | Evidence | Status |
| --- | --- | --- | --- | --- |
| **High** | **Mobile hides the frozen date completely.** Age is essential when deciding what to consume first. “Oldest first” produces an unexplained order when dates are invisible. | Keep a compact age label on every card, such as **Frozen 12 days ago** or **12 Aug**. Highlight old stock and ensure visible dates explain the chosen sort order. | `src/App.css:1576`, `src/components/InventoryPanel.tsx:175` | [x] Fixed |
| **High** | **The add flow can create accidental phantom inventory.** A new draft starts as Chicken · Breast · 500 g · Home, and every step is immediately valid. Users can repeatedly press Next and save data they never intentionally chose. | Require explicit category selection for new entries. Defaults may remain for quantity and freezer after category selection. Alternatively label them as suggested defaults and require a clear final review. | `src/App.tsx:68`, `src/App.tsx:310` | [x] Fixed |
| **High** | **Storage loading, empty, and failure are indistinguishable.** IndexedDB queries default to empty arrays without a recoverable query-error state. A slow or failed database can look like an empty freezer. | Introduce explicit `loading`, `ready`, and `error` states. Show a short skeleton while IndexedDB opens and a persistent error with **Retry** and backup/recovery guidance. | `src/App.tsx:137` | [x] Fixed |
| **High** | **Household migration and membership actions lack protection and progress.** Migration, invite revocation, member removal, and sign-out run immediately; controls remain enabled while requests are pending. | Add per-action pending states. Require confirmation for migration, removing members, and revoking invitations. Explain migration scope, reversibility, offline consequences, and the resulting source of truth before confirmation. | `src/components/HouseholdSyncPanel.tsx:46` | [x] Fixed |
| **High** | **Editing is appended below the inventory instead of becoming the active task.** There is no scroll or focus management. In a long inventory, the editor may open outside the viewport; on mobile the persistent Add FAB can overlap edit content. | Open editing as a dedicated sheet, dialog, or view. Move focus to its heading or first field, hide the FAB, support Escape/Back, and restore focus to the edited card when closed. | `src/App.tsx:798`, `src/App.css:1219` | [x] Fixed |
| **High** | **Undo may be invisible when removing an item lower in a long list.** The item disappears immediately, while the five-second undo message is inserted near the top of the page. | Use a fixed bottom snackbar above the FAB: **Chicken breast removed — Undo**. Keep it visible for 8–10 seconds and pause dismissal while focused or hovered. | `src/App.tsx:371`, `src/App.tsx:711` | [x] Fixed |
| **Medium** | **The first-use empty state says “Nothing matched the current search” when no search exists.** It tells users to add an item but offers no action. Filtered-zero and genuinely empty inventory share one state. | Build separate states: **first use** with an Add CTA and value explanation; **no search results** with query text and Clear search; **no filter results** with Reset filters; and a separate history empty state. | `src/components/InventoryPanel.tsx:141` |
| **Medium** | **“Newest first” in History sorts by creation date, not removal date.** Recently removed older items can appear deep in history. | In History, sort by `takenOutAt`. Rename the options contextually to **Recently removed** and **Oldest removal**, and show the removal date on cards. | `src/lib/inventory.ts:44` |
| **Medium** | **The inventory summary silently hides categories.** Only the first three populated categories in catalog order are shown, without a “more” indicator. | Show top categories by count plus **+N categories**, make cards filter the list, or replace them with stronger decision signals such as oldest item and freezer-location totals. | `src/App.tsx:723` |
| **Medium** | **The five-screen add flow is heavy for a frequent household action.** Category, cut, quantity type, quantity, and notes each require a separate step, followed by an additional success screen. | Use a two-stage flow: **Item** (category + cut) → **Details** (amount + freezer + optional note). After saving, return directly to inventory with a snackbar and **Add same again** action. | `src/App.tsx:56` |
| **Medium** | **Closing add or edit discards work without warning.** There is no dirty-state detection, and browser Back/Escape are not integrated. | Preserve drafts until saved or explicitly discarded. When dirty, confirm with **Keep editing** and **Discard changes**. Support browser Back and Escape consistently. | `src/components/AddFlow.tsx:75`, `src/components/EditItemPanel.tsx:193` |
| **Medium** | **Optional shared mode appears as a red error when unconfigured.** Local-only users encounter an alarming dead end even though sharing is explicitly optional. | Show a neutral, collapsed section: **Household sharing isn’t enabled in this build.** Reserve red error treatment for a configured feature that subsequently fails. | `src/components/HouseholdSyncPanel.tsx:76` |
| **Medium** | **Invitations and members are difficult to identify safely.** Members display raw user IDs; outstanding invitations show only an expiry date, making removal and revocation error-prone. | Display member email/name and role. Identify invitations by recipient or creation time, show expiry, and generate a shareable invitation link instead of using a raw token as the primary method. | `src/components/HouseholdSyncPanel.tsx:80` |
| **Medium** | **Invalid quantity has insufficient feedback.** In Add, Next simply becomes disabled; in Edit, validation appears only after Save. Non-weight units are editable free text in Edit. | Use numeric constraints and inline validation: **Enter an amount greater than 0.** Keep pack/piece units read-only and derive them from quantity type. | `src/components/AddFlow.tsx:270`, `src/components/EditItemPanel.tsx:96` | [~] Partial — edit units are read-only |
| **Low** | **Tabs and the full-screen add experience only partially implement expected keyboard/dialog behavior.** Tabs use roles and roving `tabIndex` but have no arrow-key navigation; Add does not announce itself as a dialog or manage focus. | Add Left/Right/Home/End tab behavior. Implement Add/Edit with dialog semantics, initial focus, focus containment, Escape, and focus restoration. | `src/components/InventoryPanel.tsx:48`, `src/components/AddFlow.tsx:69` |

## Recommended implementation order

1. Restore frozen-date visibility.
2. Remove accidental add defaults or require explicit selection.
3. Implement storage loading and error states.
4. Turn Edit into a focused sheet/view and fix the undo snackbar.
5. Protect household migration and member actions.
6. Split genuine-empty, filtered-empty, and error states.
7. Simplify the add flow.
8. Correct history sorting and summary hierarchy.
